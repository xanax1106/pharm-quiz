# 課堂即時測驗系統（GitHub Pages 版）

包含兩個功能：**課堂即時測驗**（上課時每節 5 題）與**課後練習**（每週約 30 題，學生回家自行作答）。

學生掃 QR code，用「學號＋課堂代碼」加入；每輪約 5 題，可選「逐題公布」或「連續作答」；每題統計 A、B、C、D 各幾人，公布答案、解析與重點，最後顯示本輪總結與重點整理，課後匯出成績 Excel。

- 網頁放在 **GitHub Pages**（免費，網頁上拖曳上傳即可，不必安裝軟體）
- 登入與資料庫使用 **Firebase**（免費方案）

第一次設定約 60 分鐘，之後每堂課只要上傳題庫即可。請用個人電腦操作，不要使用醫院內網或醫院電腦。

> **重要：題庫 Excel 和成績檔絕對不要上傳到 GitHub。** GitHub 免費版的儲存庫是公開的，任何人都看得到，學生可能搜尋到答案。

## 第 1 步：準備
- 一個 Google 帳號（建議另開教學專用帳號）
- 一個 GitHub 帳號（https://github.com 免費註冊）
- 解壓縮本資料夾

## 第 2 步：建立 Firebase 專案
1. 開啟 https://console.firebase.google.com ，用 Google 帳號登入。
2. 按「新增專案」，名稱例如 `pharm-quiz`；Google Analytics 可關閉；按「建立專案」。

## 第 3 步：填入連線設定
1. 專案首頁按「</>」（網頁）圖示，暱稱填 `quiz`，按「註冊應用程式」。
2. 畫面會出現 `firebaseConfig = { ... }`，裡面有 6 個值。
3. 用記事本打開 `docs/firebase-config.js`，把 6 個值逐一貼上，取代「請填入」，存檔。

## 第 4 步：開啟登入功能、建立資料庫、設定教師帳號
1. 左側「Authentication」→「開始使用」→「登入方式」：啟用「電子郵件／密碼」與「匿名」。
2. 「使用者」分頁 →「新增使用者」：輸入您的電子郵件與一組強密碼（這就是教師帳號），新增後複製「使用者 UID」。
3. 左側「Firestore Database」→「建立資料庫」→ 位置選 `asia-east1`（台灣）→「正式版模式」→ 建立。
4. 按「開始集合」：集合 ID 填 `teachers`；文件 ID 貼上 UID；新增欄位 `name`（字串），填您的稱呼，儲存。

## 第 5 步：套用安全規則（一定要做）
1. Firestore Database →「規則」分頁。
2. 用記事本打開 `firestore.rules`，全部複製，貼上取代原本內容，按「發布」。

## 第 6 步：上傳到 GitHub 並開啟網站
1. 登入 GitHub，右上角「＋」→「New repository」。
2. Repository name 填 `pharm-quiz`，選 **Public**，按「Create repository」。
3. 在新頁面點「uploading an existing file」。
4. 把解壓縮後資料夾**裡面的所有內容**（`docs`、`tools` 資料夾與 `README.md`、`CLAUDE.md`、`firestore.rules`）一起拖進網頁。
5. 確認清單中**沒有任何 Excel 檔**，按綠色「Commit changes」。
6. 到儲存庫的「Settings」→ 左側「Pages」：
   - Source 選「Deploy from a branch」
   - Branch 選 `main`，資料夾選 `/docs`，按「Save」
7. 約 1–3 分鐘後重新整理，頁面上方會顯示網址，例如 `https://您的帳號.github.io/pharm-quiz/`。
   - 教師控制台：`https://您的帳號.github.io/pharm-quiz/teacher.html`
   - 學生掃投影幕上的 QR code 即可，不必記網址。

## 第 7 步：加強安全設定
1. **授權網域**：Firebase「Authentication」→「設定」→「已授權網域」→「新增網域」，填 `您的帳號.github.io`。
2. **限制 API 金鑰**（建議）：
   - 開啟 https://console.cloud.google.com ，上方選擇同一個專案。
   - 左側「API 和服務」→「憑證」→ 點「Browser key (auto created by Firebase)」。
   - 「應用程式限制」選「網站」，新增 `https://您的帳號.github.io/*`，儲存。
   - 若之後登入失敗，先暫時移除此限制確認是否為設定問題。

`firebase-config.js` 的值會隨網站公開；這是所有 Firebase 網頁的共同狀況，這些值本身不是密碼。真正保護資料的是第 5 步的安全規則，加上第 7 步限制只能從您的網址使用。

## 第 8 步：上課前測試（強烈建議）
1. 電腦開教師控制台並登入，上傳 `題庫範本.xlsx`，選擇作答方式，按「建立課堂並產生代碼」。
2. 按「開啟投影畫面」，拖到投影機螢幕，按 F11 全螢幕。
3. 用自己的手機掃 QR code，輸入任一測試學號加入。
4. 一直按綠色主按鈕跑完整個流程，確認手機與投影畫面同步。
5. 按「匯出成績 Excel」確認檔案內容。

## 測試模式（給自己和朋友試用）

建立課堂時勾選「測試模式」：

- 朋友不必輸入學號，只要輸入**暱稱**即可加入。
- 課堂代碼會自動帶入，朋友不需要另外輸入。
- 朋友在現場：掃投影畫面上的 QR code。
- 朋友在遠端：控制台上課畫面有「遠端測試」區塊，按「複製加入連結」用 LINE 傳給朋友，或讓他們掃控制台上的小 QR code。

建議測試項目：

| 項目 | 確認重點 |
|---|---|
| 加入 | 掃碼後能否順利加入，控制台人數是否增加 |
| 逐題公布 | 作答、截止、公布答案時，手機與投影畫面是否同步 |
| 連續作答 | 手機是否一次看到全部題目，截止後能否逐題檢討 |
| 總結與重點 | 本輪總結的排序與重點整理是否正確顯示 |
| 重新整理 | 作答中手機重新整理，是否自動回到課堂 |
| 匯出 | 成績 Excel 的內容是否正確 |
| 簡報器 | 投影畫面能否用簡報器翻頁鍵推進 |

## 上課流程

教師控制台的**綠色主按鈕會自動顯示下一步**，照著按即可。投影畫面上也能用**簡報器翻頁鍵**或鍵盤（→、PageDown、空白鍵）執行下一步，不必回到電腦。

**逐題公布模式**

開始第 1 題 → 截止作答（投影幕出現 A、B、C、D 人數）→ 公布答案與解析 → 下一題 … → 本輪總結 → 重點整理 → 結束本輪

**連續作答模式**

開始作答（學生手機一次看到全部 5 題）→ 截止作答，開始逐題檢討 → 公布答案與解析 → 檢討下一題 … → 本輪總結 → 重點整理 → 結束本輪

開始作答前，可在控制台切換兩種模式。

| 畫面 | 投影幕 | 學生手機 |
|---|---|---|
| 作答中 | 題目、插圖、全班作答牆（灰色＝已作答，不顯示選了什麼） | 點選答案，截止前可改 |
| 截止作答後 | 各選項人數與百分比；作答牆顯示每人選的字母 | 自己選了什麼 |
| 公布答案 | 正確答案、答對率；**每個選項旁標示對錯原因與人數**；作答牆綠色答對、紅色答錯；詳細解析與重點 | 對錯；**答錯時顯示「你選 X：錯在哪裡？」**；詳細解析與重點 |
| 本輪總結 | 5 題各選項人數，依答對率由低到高排列，低於 60% 標紅 | 自己每題的對錯 |
| 重點整理 | 本輪 3–5 點重點 | 同步顯示，可截圖 |

**座號登入**：學生輸入座號即可（1–3 位數字，系統自動補成 3 碼，例如 7 → 007），也可輸入完整學號；匯出成績時以座號對照班級名單。

**全班作答牆**：建立課堂時可選「顯示座號（學號末 3 碼）與對錯」（預設）、「只顯示顏色」或「不顯示」。若發現學生因怕被看到答錯而不敢作答，可改為只顯示顏色。

**講解建議**：截止或公布後，教師控制台會依答對率提示講解方式（80% 以上快速帶過；40–80% 請選錯最多選項的同學說理由；40% 以下重新講觀念）。

小技巧：截止作答後先別公布，請選錯最多的同學說說為什麼選這個，再公布解析，討論效果最好。本輪總結時，挑答對率最低的題目再多講幾分鐘。

## 課後練習（每週約 30 題）

建議每週第 3 節下課前發布，下次上課前關閉。

1. 教師控制台首頁「建立課後練習」：輸入名稱、上傳題庫 Excel，按「建立課後練習」。
2. 進入成績頁後，按「複製作答連結」用 LINE 傳給學生，或讓學生掃頁面上的 QR code。
3. 學生輸入學號後作答；作答進度會自動保存，可以分次完成。
4. **每人只能交卷一次**，交卷後立即看到分數、正確答案、「你選 X：錯在哪裡？」、詳細解析與本週重點（答錯的題目排在前面）。
5. 成績頁即時顯示：已交卷人數、平均答對率、最低／最高分、逐題答對率（由低到高，含「下週開場建議」：最多人誤選的選項與原因）、每位學生成績。
6. 下次上課前按「關閉練習」，按「匯出成績 Excel」保存。逐題答對率最低的題目，可以在下次上課開場時複習。

| 設計 | 說明 |
|---|---|
| 題目組成 | 建議 24 題本週＋6 題複習（第 1 週為先備知識），在 Excel「類別」欄標示 |
| 防作弊 | 每位學生的題目與選項順序不同；交卷前拿不到答案；交卷後不能修改 |
| 計分 | 不計入成績，純練習；分數由後台依原始作答計算 |
| 限制 | 學生若換一台裝置，系統會視為新的作答者，成績頁會標示「重複學號」 |

## 題庫製作
- 使用 `題庫範本.xlsx`：「題庫」工作表每列一題（課堂測驗每輪 5 題、課後練習約 30 題），「本輪重點」工作表每列一點。
- 「類別」欄填「本週」或「複習」，課後練習才需要。
- 「重點」欄是每題一句話的記憶重點；「來源」欄只有老師看得到。
- 「錯誤說明A～D」欄：每個選項為什麼對或錯（正確選項可寫「正確：……」）。公布答案時顯示在投影幕，答錯的學生手機上也會看到自己選項的說明。可留白。
- 「插圖」欄：填插圖代號，題目旁會顯示對應插圖；留白則不顯示。可用代號（檔案在 `docs/img/`）：
  `pk` 送貨卡車、`pd` 鑰匙開鎖、`cover` 藥瓶、`forms` 各種劑型、`boxes` 藥盒、`coldmed` 感冒藥與水杯、`rx` 處方箋、`dropper` 量杯與滴管、`ivbag` 點滴、`vaccine` 疫苗、`contrast` 顯影劑、`iud` 子宮避孕器、`vitamin` 維生素、`flask` 燒瓶與 DNA、`liver` 肝臟、`kidney` 腎臟、`brain` 大腦與屏障、`poppy` 罌粟、`foxglove` 毛地黃、`tea` 茶、`check` 清單、`phone` 手機、`students` 學生。
- 新增插圖：把 PNG 檔（建議寬 360 像素、檔名只用英數字）放進 `docs/img/`，Excel 填檔名（不含 .png）。
- 題庫檔只存在自己的電腦，上課時從控制台上傳。

## 修改網站
在 GitHub 儲存庫點進檔案 → 右上角鉛筆圖示編輯 → 「Commit changes」，1–3 分鐘後網站自動更新。若修改了 `firestore.rules`，記得也要到 Firebase 主控台重新貼上並發布。

## 常見問題
| 狀況 | 原因與處理 |
|---|---|
| 打開網站顯示「尚未填入專案設定」 | `docs/firebase-config.js` 沒有填好，或上傳的是舊檔 |
| 學生說「找不到課堂代碼」 | 代碼輸入錯誤，或該輪已結束 |
| 學生說「送出失敗」 | 已截止作答，或網路中斷；請學生重新整理頁面 |
| 投影畫面顯示「請先登入」 | 投影畫面要在同一個瀏覽器、已登入教師控制台時開啟 |
| 簡報器沒反應 | 先用滑鼠點一下投影畫面，讓視窗取得焦點 |
| 控制台出現「重複學號」 | 同一學號用兩支裝置加入，或學號打錯，請現場確認 |
| 登入後顯示「尚未設定教師權限」 | 第 4 步的 UID 貼錯，畫面上會顯示正確的 UID |
| 網站改了但沒更新 | 等 1–3 分鐘，或按 Ctrl＋F5 強制重新整理 |

## 資料與個資
- 系統只儲存學號與作答紀錄，不收集姓名；投影幕不顯示學號。
- 資料存放在 Google Firebase（台灣機房 asia-east1）。
- 學期結束後，建議匯出成績，再於 Firestore 主控台刪除 `sessions` 與 `codes` 集合的資料。
- 請先確認學校對學生個人資料存放於雲端服務的規定。
